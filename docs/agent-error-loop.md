# Петля «помилка агента → правило»

Кожна помилка агента стає записаним правилом з походженням, а журнал запусків показує, чи
правило її зменшило. Інструменти — лише Markdown і один JSONL, без скриптів (див. «Огляд»).

## Де живуть уроки

`.claude/agent-memory/<agent>/` (`planner`, `generator`, `healer`): один урок — один файл, плюс
індекс `MEMORY.md`, по рядку на урок. Урок без `class` і `origin` — не правило.

```markdown
---
name: api-first
description: A UI scenario only for what the user sees; what the API alone proves goes to "API tests"
metadata:
  type: feedback
  class: pyramid-level
  origin: '2026-10-28 a7d0876: UI scenarios planned for rules the API alone proves'
  since: 2026-10-28
---

Що сталося і правило, 2–5 рядків.

**Why:** конкретне падіння.
**How to apply:** коли правило спрацьовує.
```

**Пише уроки лише головна сесія і передає їх агенту в брифі.** Агенти planner, generator, healer
приходять з `npx playwright init-agents`, і повторний init перезаписує їхні файли, тож
`memory: project` чи текст правила там би зникли. Тому бриф (`specs/README.md`) містить індекс
уроків агента і просить у звіті розділи **Learned** (кандидати в уроки) і **Errors** (класи
помилок цього запуску). Урок з кандидата записує головна сесія після перевірки.
`test-reviewer` лише читає код і пам'яті не має: його правила — у його промпті, а його знахідки
мають клас з таблиці нижче.

## Класи помилок

Короткі slug-и, спільні для всіх агентів. Новий клас — лише для нового виду помилки.

| class               | що це                                                                                |
| ------------------- | ------------------------------------------------------------------------------------ |
| `env-not-ready`     | стек, БД чи setup page не працює, а агент іде далі                                   |
| `wrong-seed`        | не той seed: стан першого візиту недосяжний                                          |
| `unsafe-tool`       | `browser_run_code_unsafe` чи інший непрозорий скрипт замість покрокових дій          |
| `bloated-scenario`  | сценарій перевіряє кілька вимог або має > 5 кроків                                   |
| `layer-bypass`      | `page.request` чи сирий запит замість `ApiClient`; локатор поза page object           |
| `pyramid-level`     | UI-сценарій для того, що доводить сам API                                            |
| `auth-state`        | неправильний стан входу: API-логін там, де потрібен токен у localStorage, тощо        |
| `test-data-leak`    | тест лишає дані в БД або залежить від даних іншого тесту                             |
| `weak-assert`       | тест зелений, але вимогу не доводить (мутант виживає)                                |
| `plan-dropped`      | сценарій плану пропущено чи послаблено без причини                                   |
| `flaky-masked`      | retries, `test.skip`, довший таймаут чи слабший matcher ховають справжнє падіння      |
| `fragile-locator`   | CSS/текст/nth там, де є `data-testid`                                                |
| `hard-wait`         | `waitForTimeout` чи поллінг замість web-first assertion                              |
| `missed-update`     | змінено page object чи фікстуру, але не виклики, документи чи конфіг                 |
| `brief-misapply`    | агент зробив не те, що в брифі                                                       |
| `wrong-scope`       | змінено файли поза завданням                                                          |

## Журнал запусків

`.claude/agent-memory/runs.jsonl`, рядок на запуск агента. Дописує **головна сесія після
перевірки** роботи агента, не сам агент:

```json
{"date":"2026-10-30","agent":"generator","step":"9.6","task":"daily tasks specs","status":"done","errors":["weak-assert"],"redone":false}
```

- `status`: `done | partial | blocked`;
- `errors`: класи, які справді трапились, **і ті, що вже покриває урок** — це сигнал, що урок не
  працює. Для generator і healer сюди йдуть знахідки `test-reviewer` на їхньому diff і мутанти,
  що вижили;
- `redone`: головній сесії довелось переробити частину роботи.

Журнал — знаменник: без нього «помилок поменшало» не виміряти.

## Огляд (раз на місяць або після кожного блоку фази 2)

Для кожного уроку — частка запусків цього агента з його класом до і після `since`:

- 0 повторів за ≥ 10 запусків → правило переходить у бриф-шаблон (`specs/README.md`), урок
  видаляється;
- повторюється → переписати правило або замінити автоматичною перевіркою (eslint, hook, guard у
  `npm run check`): перевірка сильніша за нагадування;
- класу не було 60 днів → урок видалити: уроки займають контекст агента;
- по агенту: частка `done / partial / redone`.

Спершу журнал читається вручну; скрипт звіту — після ~30 записаних запусків.
