# Модуль 6. CI, звіти, теги і масштаб

**Після модуля ти можеш:** пояснити CI-пайплайн для e2e з приватним застосунком і БД, читати
звіти й trace, обрати політику ретраїв і масштабувати прогін шардингом.

Файли: [.github/workflows/e2e.yml](../../.github/workflows/e2e.yml) ·
[playwright.config.ts](../../playwright.config.ts) · [package.json](../../package.json)

> Workflow написаний за брифом, але **ще не запускався**: потрібен секрет `APP_REPO_TOKEN`
> (fine-grained token, Contents: read на `ryanchynskyi/qa-interview-tests`). Перший запуск —
> частина практики.

## 1. Пайплайн

```
checkout framework → checkout app (token) → setup-node (cache npm для обох lock-файлів)
→ npm ci (app) → npm ci → typecheck → lint → playwright install --with-deps chromium
→ playwright test (webServer піднімає stack.mjs; Postgres — service container)
→ upload playwright-report (навіть якщо тести впали: if: !cancelled())
```

- **Postgres як service**, а не embedded: `DB_URL` у env змушує `stack.mjs` не стартувати свій
  сервер. API сам створює, мігрує і сідить БД `qahub_pw`.
- **typecheck і lint до тестів**: дешеві перевірки першими. Пропущений `await` має падати за
  секунди, а не після 5 хвилин e2e.
- **`--with-deps`** ставить системні бібліотеки браузера на чистий Ubuntu-раннер.
- **Артефакт з `if: !cancelled()`**: звіт найпотрібніший саме тоді, коли тести впали.

## 2. Прод-смоук окремою джобою

`prod-smoke` запускається лише вручну (`workflow_dispatch`), з `TARGET=prod`: без checkout
застосунку, без БД, без секретів. Конфіг сам обмежить набір до `@prod-safe`. Логічний наступний
крок — запуск за розкладом (`schedule: cron`) як моніторинг.

## 3. Теги як інтерфейс

| Тег | Хто читає |
|---|---|
| `@smoke` | людина, якій треба швидко («чи живе?») |
| `@prod-safe` | конфіг: єдиний дозволений набір для `TARGET=prod` |
| `@responsive` | конфіг: що запускати на tablet/phone |

Теги задаються через `{ tag: [...] }` у `test`/`describe`, а не в назві: так вони структуровані,
видимі у звіті і фільтруються `--grep`.

## 4. Звіти і trace

- Локально `list` у консоль + HTML (`npm run report`), на CI `github` (анотації прямо в PR) + HTML
  артефактом.
- Trace (`retain-on-failure`) — головний інструмент дебагу: DOM-знімки до і після кожного кроку,
  мережа (включно з API-запитами фікстур), консоль. `npx playwright show-trace <zip>` або
  https://trace.playwright.dev.
- `error-context.md` поруч з падінням: aria-знімок сторінки в момент помилки. Його зручно
  вставляти в issue або давати AI-асистенту.

## 5. Ретраї: допомога чи маскування

`retries: 1` на CI: тест, що пройшов з другої спроби, позначається **flaky** і видимий у звіті.
Ретрай не лікує флакі, він лише не блокує мерж, поки ти його лагодиш. Більше ретраїв ховає
проблему. Локально 0: флакі має бути видно одразу.

## 6. Масштаб: шардинг

```bash
npx playwright test --shard=1/4 --reporter=blob   # на кожній з 4 машин
npx playwright merge-reports --reporter=html ./all-blob-reports
```

`fullyParallel: true` дозволяє ділити не файли, а окремі тести, тож шарди рівніші. Межа
масштабу: спільний стек. 4 шарди на одній БД — норм, бо дані ізольовані, але `webServer` кожного
шарда піднімає свій стек (свій раннер).

## Експеримент (15 хв)

1. Запусти `npx playwright test --reporter=github` локально: як виглядають анотації?
2. Зламай один тест, запусти з `--retries=2` і відкрий HTML-звіт: як позначено ретраї?
3. `npx playwright test --shard=1/2` і `--shard=2/2`: чи покривають разом увесь набір?

## Практика (1–1.5 год)

**Завдання A. Перший зелений CI.** Створи `APP_REPO_TOKEN`, запусти workflow, полагодь те, що
впаде (типові підозрювані: шляхи `APP_DIR`, час збірки web, `node` версія).
- [ ] Зелений прогін, звіт в артефактах.

**Завдання B. Шардинг + merge.** Матриця `shard: [1, 2]`, blob-звіти артефактами, окрема джоба
`merge-reports` з одним HTML.

**Завдання C. Нічний прод-смоук.** `schedule` о 06:00 Києва (подумай про UTC у cron),
`@prod-safe`, сповіщення при падінні (наприклад, issue або повідомлення в Telegram).

## Питання на співбесіді

3. Яка ваша політика ретраїв і чому?
4. Як дебажите тест, що падає лише на CI?
